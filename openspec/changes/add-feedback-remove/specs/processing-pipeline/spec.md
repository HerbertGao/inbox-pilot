## 新增需求

### 需求:降噪反馈两触发——interpret 干跑无写、apply 幂等落盘，加入与移出共用同一条流

pilot **必须**认两个反馈触发：`interpret-feedback`（input 原始自然语言 `{text}` → emit `interpretation.proposed { add: string[], remove: string[] }`、**无任何域写**）与 `apply-feedback`（input `{ add: string[], remove: string[] }` → 应用 → emit `feedback.applied { added, already_present, removed, not_present }`）。**加入与移出必须共用这同一对触发**——撤销是同一意图的反向，**禁止**为撤销新增触发名。未知触发名仍**必须**抛错（`run.failed`），**禁止**静默走轮询。

**字段恒在**：上述两事件的**每个**声明字段**必须**恒出现，无变更即空数组，**禁止**省略——上层逐字段校验 `string[]`，缺一个即整条命令落契约不符。

**提案值即将写入的形态**：`add`/`remove` **必须**是已归一、已校验的 canonical 条目（见 `rules-config` 的 overlay 写入语义），**禁止**只复述用户原话——否则人确认的与实际写入的可能不同。

**方向判定与候选集**：一次提案**必须**只解一个方向，由**确定性关键词**判定（**禁止**引入 LLM / freetext 意图解析）：

- **移出**方向的候选集 = **当前 overlay 内容**（只读加载），故 `remove` 恒为 overlay 的子集；
- **加入**方向的候选集 = 与每日摘要展示同源的最近高频发件人 TOP-N，**并**文本里的显式地址。

两侧候选集高度重叠（刚加入降噪的发件人仍在最近高频榜上），故**必须**先定方向再解析；两侧同时求解会使同一地址同时落 add 与 remove、撞上「同址两侧」裁决而使正常用法全部失败。

**显式地址入口**：文本里带 `@` 的 token、或末段为纯字母（≥2 位）的带点 token，**必须**当作显式条目并按 `rules-config` 的入口校验处理；加入方向**禁止**再要求它出现在 TOP-N 候选里（加一个从未见过的地址是可逆低风险操作）。文本里出现显式条目时**必须**跳过子串匹配——用户已点名确切地址，模糊匹配只会引入 `com` 这类通用短 token 的误命中。

**应用侧独立校验**：`apply-feedback` 是**独立入口**，**禁止**信任上层回传的结构化结果——**必须**重新归一 + 重新校验（见 `rules-config`），非法即抛错。

**跨仓部署序必须为 pilot 先、view 后**：pilot 多 emit 字段对旧 view 无害（旧 view 只投影自己声明的字段），反序则整条命令路径落契约不符。

#### 场景:提案阶段无任何写
- **当** `interpret-feedback` 完成
- **那么** run **必须**只 emit `interpretation.proposed`，overlay 与 `rules.yaml` 的内容与 mtime **必须**均未变

#### 场景:两事件字段恒在
- **当** 一次提案或应用没有解出/产生任何变更
- **那么** 事件里声明的字段**必须**全部出现且为空数组，**禁止**省略任何一个

#### 场景:移出走同一对触发、候选集为 overlay
- **当** 用户下达「把某发件人从降噪名单移出」
- **那么** **必须**走同一对 `interpret-feedback`/`apply-feedback`（无新触发名），`add` 为空、`remove` 为 overlay 内命中的 canonical 条目；不在 overlay 的地址**禁止**进入提案

#### 场景:显式地址不受 TOP-N 限制
- **当** 用户在文本里点名一个从未出现在高频候选里的合法地址
- **那么** 该地址**必须**以 canonical 形态进入 `add`；同一文本里的子串模糊匹配**必须**被跳过

#### 场景:非法显式地址响亮失败
- **当** 文本里点名的地址非法（空值、控制字符、非法 mailbox/domain、非 ASCII 域名）
- **那么** run **必须**以失败结束（供上层呈现「命令失败 · 回 CLI trace」），**禁止**静默忽略该地址

#### 场景:同址同时加与移被拒
- **当** 应用的 input 里同一地址（归一后）同时出现在 `add` 与 `remove`
- **那么** **必须**抛错，**禁止**静默任选一边或抵消成无操作，且 overlay **必须**未被写

#### 场景:未知触发名响亮失败
- **当** 命令用了 pilot 不认识的触发名
- **那么** run **必须**以失败结束，**禁止**静默走轮询或伪装成功
