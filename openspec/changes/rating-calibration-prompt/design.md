## 上下文

- **prompt 现状**（`src/classifier/prompt.ts:14-41`）：P0 定义含「交易、告警」（一刀切），P4 = 「任何疑似钓鱼、诈骗、异常登录、支付风险」。口径过宽是过度评级的源头。
- **prompt.ts 的权威源是 PROJECT_INIT §11**（`prompt.ts:1` 注释自承「PROJECT_INIT §11 原文」；CLAUDE.md 指 PROJECT_INIT 为「完整需求权威」）——收紧必须同步 §11，否则文档（宽）与代码（紧）漂移。
- **过度评级实证**：接入当天 1189 封旧邮件，P0–P2 占 93%、仅 5.6% 进 P3。
- **关键基建事实（决定本 change 形态）**：本仓 **CI 无 `OPENROUTER_API_KEY`**；分类测试（`src/classifier/classifyEmail.test.ts`）全部**注入假 `chatSpy`**——脚本写死响应、不经真实 prompt；规则测试是纯函数。**改 prompt 在现有离线基建里等于没测**。
- **硬约束**：prompt 只是最佳努力约束（`email-classification/spec.md`「分类 Prompt 安全约束」明示），强制裁定在规则引擎；prompt 误评只能误判、清不掉「P4/敏感不自动已读」硬底线。

## 目标 / 非目标

**目标：**
- 收紧 prompt 把系统性过度评级压下来（P4 收窄到内容层欺骗、P0 去一刀切）。
- **不削弱真钓鱼检测**——双向回归语料守门，证明非对称收紧只让误报下降、不放过真威胁。

**非目标：**
- 不改规则引擎 `applySafetyRules` 或动作执行（硬底线不动）。
- 不在本 change 敲定 eval 基建的最终实现——先定**机制方向**（见未解问题），实现可拆后续。

## 决策

**决策 1：非对称收紧（只收表层触发，内容欺骗仍偏 P4）。**
单向收紧 prompt 的风险是「放过真钓鱼」。非对称收紧把风险锁死在**误报下降**方向：P4 仅由「内容层欺骗证据」触发，表层信号（可疑 TLD / 截断 / 未渲染模板 / 单独 return-path）不单独构成 P4——这些恰是命中自有转发域时的常见假阳性来源。**prompt 仍正向指示真钓鱼 / 内容欺骗归 P4**（收紧的是触发条件、不是移除 P4）。
- 备选：对称放宽阈值 / 加权打分 → 否决，会同时降低真钓鱼召回。

**决策 2：双向回归语料 + 非对称守门语义（安全线逐样本、噪音线阈值）。**
误报集（网易登录 / PayPal 收据 / HKSS / 交易收据）+ 真钓鱼集。守门**两侧语义不同**（消除「逐样本 vs 阈值」的内部矛盾）：
- **真钓鱼集 = 逐样本 hard-fail（安全线、无阈值）**：任一真钓鱼掉出 P4 即校准失败。这是 prompt 收紧唯一的安全护栏，不容抖动吸收。
- **误报集 = 通过率阈值（噪音线，≥Y% 降出 P0/P4 即通过）**：误报方向是噪音问题非安全问题，允许阈值吸收 LLM 抖动（偶尔多推一封 = 噪音回潮，非安全回归）。
spec 因此用「真钓鱼**禁止**掉出 P4（MUST，逐样本）」+「误报**应**降级（SHOULD，阈值）」区分二者。

**决策 3：真钓鱼语料的代表性是守门价值上限（机制只是执行层）。**
合成 / 脱敏钓鱼样例若与真实钓鱼分布有偏（合成样例常「太像教科书钓鱼」、内容欺骗信号过显著），阈值会给虚假安全感——eval 全绿但边缘钓鱼仍失守。语料**必须**覆盖「**表层信号弱、内容欺骗强**」的边缘样例——这正是非对称收紧最可能误伤的一类（收紧后正靠「内容层欺骗证据」托底）。

**决策 4：四重拆弹（安全护栏，详见 proposal）。**
① 引擎硬底线原封不动；② 真钓鱼反向语料守门；③ 非对称收紧；④ `confidence<0.65→P1` 兜底。

## 风险 / 权衡

- **[收紧致真钓鱼漏判 = 安全事故]** → 真钓鱼逐样本 hard-fail 守门（决策 2）+ 引擎硬底线不动 + confidence 兜底。这是本 change 最大风险，需独立安全评审。
- **[残差风险量化：即便真钓鱼在两次守门之间漏过 P4]** → **桥接论证**：prompt 误评只能误判 → 引擎硬底线仍拦自动已读（P4/敏感永不自动已读）→ 真钓鱼即便掉出 P4 仍**不会被自动已读 / 自动处理**，唯一损失是「未进 P4 即时推送」而非「被错误放行」。故残差是「漏一次 P4 推送」（可恢复、非实时安全事故），**这正是 nightly 非阻塞守门对噪音线可接受、而真钓鱼安全线仍用逐样本 hard-fail 的理由**。
- **[LLM 非确定致 eval flaky]** → 仅误报线用阈值吸收抖动；安全线逐样本（决策 2）。
- **[prompt 改动无离线可测路径]** → 现有 `chatSpy` 引擎兜底测仍跑（保证「AI 失败/低置信→P1」不回归），但**真实 prompt 效果只能靠真调模型的 eval 守**——这正是下方未解问题。

## 迁移计划

- 改 `src/classifier/prompt.ts` 文案 + **同步 PROJECT_INIT §11 的 P0/P4 文案**（防文档/代码漂移）；**无 DB / 无迁移**。回滚 = 还原 prompt 字符串 + §11。

## 守门机制（已定案 · 经 AI Engineer + DevOps Automator 决断；原为前置未解问题）

**核心：非确定的 LLM，怎么在 CI 守住「真钓鱼仍 P4」？**（机制是执行层；决策 2/3 已定守门**语义**，此处定守门**机制**。下表为候选权衡，结论见「定案」。）

| 选项 | 做法 | 取舍 |
|---|---|---|
| **A 纯离线不真测** | 只 review prompt 文案 + 假 chatSpy 测引擎兜底 | 等于不守 ③A 真实效果，违背 roadmap「真钓鱼掉出 P4 即失败」——**不可取** |
| **B nightly 非阻塞 eval** | 定时 job 用真 key 跑语料、产通过率报告、不阻塞 PR | flaky 不卡合并；安全回归滞后到次日发现（残差由上方桥接论证界定为「漏一次 P4 推送」可接受）。需：CI secret key、语料存放、运行脚本 |
| **C PR 阻塞 eval** | 每 PR 真跑语料、低于阈值即 fail | 守门最强；但每 PR 花钱 + flaky + 需 key，对单人项目偏重 |
| **拆分守门强度（B+C 混合）** | **真钓鱼安全线 PR 阻塞（逐样本）+ 误报噪音线 nightly（阈值）** | 把成本/flaky 压在噪音线、安全线实时守门，与「真钓鱼是最高安全线」姿态自洽 |

### 定案（采纳「拆分守门 + paths 精准触发」）

1. **Cadence**：真钓鱼**安全线 = PR 阻塞 + `paths` 过滤**（仅 `src/classifier/{prompt,classifyEmail,schema}.ts` + `eval/**` 变更触发——日常无关 PR 直接 skip ⇒「PR 阻塞」零成本零 flaky，且在唯一能引入该回归的改动上当场拦截）；误报**噪音线 = nightly 非阻塞 + 阈值**。桥接论证的作用域**精确界定**：背书**误报线降 nightly** + **fork 无 key skip**，**不**用于把安全线本身降到次日。

2. **判定协议（纠正原「逐样本 hard-fail」）**：裸逐样本 hard-fail 在 `gemini-2.5-flash-lite` 上**会 flaky → 必被加 `continue-on-error` 绕过**。安全线改为**逐样本 k=5 多数表决**：同一样例跑 5 次，**≥3/5 落 P4 即 PASS，<3/5 FAIL（→ exit 1 阻塞）**——区分「单次抖动（噪音）」与「系统性误伤（信号）」。**不用「失败重试」**（只给失败方第二次机会、统计有偏；多数表决无偏）。误报线 **k=1、通过率阈值 Y=70%**（单用户小语料下 90% 过苛必 flaky；70% 容 3–4 条抖动仍证系统性下降）。

3. **语料（决策 3 落地）**：按「**表层信号 × 内容欺骗**」二象限矩阵构造，价值由**象限B（表层弱+内容强）**覆盖密度决定、非总条数。真钓鱼 **8–12 条（象限B ≥50%、象限A 教科书钓鱼 ≤30% 封顶**防虚假安全感）+ 误报 10–15 条、配比 ≈1:1.5（刻意让误报多、回归主力在误报方向）。评审准则进 PR checklist：逐样本标两轴、象限A 配额封顶、对象限B 做「**删表层信号后仅凭正文人类仍能判钓鱼吗**」压测剔伪装样本、覆盖中文 5 类钓鱼子型（仿冒银行/支付催缴·HR/offer·同事上级转账·账号到期续费·物流补缴）。

4. **真脱敏 vs 合成 = 混合**：**象限B 必须真脱敏**（合成/LLM 生成会**系统性偏到象限A**、写不出隐晦内容欺骗）；象限A/C/D 可合成。脱敏只动 PII、**保语用结构**（话术/紧迫感/欺骗前提逻辑链）、链接断活性（`hxxp://placeholder.example`）、**存文本投影不存 `.eml`**（同解隐私 + 仓库不存活恶意内容）。

5. **CI key + 成本**：**配 `OPENROUTER_API_KEY` secret**；成本 **< $0.5/月**（安全线每轮 ~10×5=50 次 flash-lite 调用 <1¢；nightly 30 次×~$0.012）= 可忽略、**不建任何成本治理机制**（YAGNI）。用 **`pull_request`（非 `pull_request_target`）**：fork 拿不到 secret → eval 检测无 key → **skip 标绿**（复用 `classifyEmail` 缺 key 安全默认、不抛异常），零 secret 泄露面。

6. **基建分离**：eval 落 `src/classifier/eval/`、文件**不带 `.test.ts`**（天然不被 `node:test` glob 收集）、独立 `pnpm eval` runner（自印通过率表 + 退出码，不用 `node:test` 断言模型）、新增 `.github/workflows/eval.yml`（安全线 PR 阻塞 + 噪音线 `schedule:` nightly）；`ci.yml` 与 `pnpm test` 零改动。flaky 控制：复用 `openrouterClient` 既有 20s 超时 + `classifyEmail` 内置「单次重试+fallback」状态机，**外层不再加重试**；语料小，串行/≤5 并发、无并发框架。nightly 失败 → `if: failure()` 一行 `\gh issue`（按固定 label 去重）→ GitHub 默认 issue 通知邮件落 operator 收件箱（零额外告警通道、用自带 `GITHUB_TOKEN` 无需配 secret）。

**剩余人工动作（机制已定、需人执行，非设计未决）**：① 实现时由用户把自己的 `OPENROUTER_API_KEY` 加为 GitHub Actions secret（其账号/账单决定）；② 象限B 真钓鱼样例由用户**人工脱敏 + 标两轴**（8–12 条一次性，命中新型钓鱼时手工追加 1 条）——这是「内容欺骗强/表层弱」判定的人类语境输入，不可自动生成。spec 守门场景仍只钉**行为属性**（真钓鱼必须仍 P4），上述运行机制落在 `eval/` + `eval.yml`，不入 spec。

**模型选型备注**：生产分类器模型是 `OPENROUTER_MODEL` 一个 env 旋钮（默认 `google/gemini-2.5-flash-lite`、便宜+快、适合每封一调），与守门机制正交。免费端点（如 `openai/gpt-oss-120b:free`）**不适合生产**——免费层限速（~50 请求/天、20/分钟；充值 ≥$10 才升 ~1000/天）扛不住「接入当天 1189 封 + 多账号轮询」的每封一调吞吐，撞限速即降级安全默认 P1。若要换模型（如付费 `openai/gpt-oss-120b` 求更强质量），**须先用本节的 ③A 二象限 eval 实测**（过真钓鱼 k=5 多数表决 + 误报 Y=70% 才算合格候选），并权衡延迟/价；eval **必须跟生产同模型**（否则守门测的不是线上模型）。无论免费/付费都仍需 `OPENROUTER_API_KEY`（鉴权）。隐私：免费端点上游 provider 数据政策各异，发邮件正文前须核实（对齐「不泄露正文」硬约束）。
