## 修改需求

### 需求:分类 Prompt 安全约束
分类 prompt **必须**指示模型只输出 JSON、不输出解释性文本，并内含安全要求；但 P0/P4 口径按本次校准**收紧**（消除系统性过度评级）：

- **P4 需内容层欺骗证据**：**仅当**邮件**内容**含「诱导收件人按欺骗前提行动」的欺骗证据（如冒充身份诱导点链接 / 转账 / 交出验证码）才归 P4；**表层信号**——可疑 TLD（如 `.xyz`）、文本截断、未渲染的模板变量、`return-path` 单独出现（尤其命中自有转发域）——**禁止**单独构成 P4。
- **P0 不再一刀切**：**去除**「交易 / 告警」无差别归 P0 的指示；交易**收据**类、系统**例行**通知归 P2/P3；P0 收窄为「真正需要收件人立即亲自动手处理」者。
- 银行 / 医院 / 保险 / 合同 / 招聘 / 账单类**不要轻易**标为 P3；置信度低于 0.65 时**不要**建议自动标已读；**禁止**建议自动回复或自动发送邮件。
- 本期 prompt 只对模型做**最佳努力**约束；具强制力的最终裁定仍在规则引擎（`confidence<0.65→P1`、P4/敏感不自动已读等硬底线**不受 prompt 影响**，prompt 误评只能误判、清不掉底线）。

#### 场景:Prompt 要求只输出 JSON 且禁止建议自动收发
- **当** 构造分类 prompt
- **那么** prompt 必须要求只输出 JSON，并明确禁止建议自动回复或自动发送邮件

#### 场景:P4 需内容层欺骗证据、表层信号不单独触发
- **当** 构造分类 prompt
- **那么** prompt 必须指示「P4 需内容层欺骗证据」，并明确可疑 TLD / 截断 / 未渲染模板 / 单独 return-path 等表层信号**不**单独构成 P4

#### 场景:P0 不再一刀切交易/告警
- **当** 构造分类 prompt
- **那么** prompt 必须不再把「交易 / 告警」无差别归 P0；交易收据 / 例行通知类指示归 P2/P3

#### 场景:P4 正向口径与敏感类目约束保留
- **当** 构造分类 prompt
- **那么** prompt 必须仍含 P0–P4 定义、**仍正向指示真钓鱼 / 内容层欺骗归 P4**（收紧的是触发条件、**非移除 P4**——与「P4 需内容层欺骗证据」场景互补：一钉收紧边界、一钉正向保留，否则与下「真钓鱼禁止掉出 P4」需求自相矛盾），并指示银行 / 医院 / 保险 / 合同类不轻易标 P3

## 新增需求

### 需求:Prompt 校准的双向回归守门
prompt 校准**必须**经**双向回归语料**守门，证明收紧未削弱真钓鱼检测——**禁止**单向只验误报。系统**必须**维护两组语料：一组**真钓鱼**样例、一组**误报**样例（网易登录 / PayPal 收据 / HKSS / 交易收据类）。经校准后的 prompt 分类，**真钓鱼语料禁止掉出 P4**（任一掉出即视为校准失败），误报语料**应**降出 P0/P4。

守门**两侧语义非对称**（消除「逐样本 vs 阈值」歧义，见 design 决策 2）：**真钓鱼集为安全线、逐样本 hard-fail**（MUST，任一掉出即失败、不容阈值吸收）；**误报集为噪音线、允许通过率阈值**（SHOULD，≥阈值降出 P0/P4 即通过，吸收 LLM 抖动）。守门的**运行机制**（真钓鱼线 PR 阻塞 vs nightly、误报线阈值取值、语料存放与是否真调模型、CI 凭据与成本、**真钓鱼语料代表性/分布覆盖**）属本 change 的**前置未解问题**（见 design.md），本需求只钉**行为属性**、不钉运行机制。该守门**独立于**规则引擎硬底线：无论 prompt 如何误评，规则引擎对 P4/敏感邮件「不自动标已读」的硬底线**仍**生效。

#### 场景:真钓鱼不得因收紧掉出 P4
- **当** 真钓鱼语料经校准后的 prompt 分类
- **那么** 必须仍判 P4（任一真钓鱼掉出 P4 即视为校准失败）；且规则引擎硬底线（P4 不自动标已读、敏感邮件不自动标已读）独立于此**仍生效**

#### 场景:误报语料经校准降级
- **当** 误报语料（网易登录 / PayPal 收据 / HKSS / 交易收据）经校准后的 prompt 分类
- **那么** 应不再被高评为 P0/P4（降到 P1/P2/P3）；规则引擎对最终结果的强制裁定不被绕过
