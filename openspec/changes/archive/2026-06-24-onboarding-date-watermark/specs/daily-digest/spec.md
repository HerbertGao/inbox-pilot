## 修改需求

### 需求:每日定点构建并推送摘要
系统必须在 `DIGEST_TIMES` 配置的每个时刻（默认 `12:30`、`21:30`）触发一次摘要：查出**自上次摘要以来尚未进过摘要**
的已处理邮件，组装文案，经既有通知渠道推送。当本次**既无 P1/P2 邮件、P3 计数又为 0**（含查到行但按优先级过滤后为空）时，
**禁止**推送空摘要（记 `kind:'digest-empty'` 日志即可）；只要有 P1/P2 条目**或** P3 计数 > 0 即推送。摘要使用邮件经
规则引擎裁定后的**最终优先级**（`mail_classifications.priority`），**禁止**依据 LLM 原始建议。

纳入范围**不得**带**固定**邮件年龄上限（保停机期间积压的旧邮件不被永久排除）；但必须按该邮件所属账号的
`processFrom` 水位线（见 onboarding-watermark 能力）设 **`receivedAt` 下界**——排除 `receivedAt < processFrom` 的邮件
（即接入 / `set-process-from` 盖戳前**收到**的历史积压），边界**含界**（`receivedAt >= processFrom` 纳入）。`processFrom = NULL`
的账号**不**设下界（保持现状）。其余纳入条件不变：只要 `processedAt != null`、未进过摘要、且通过该账号水位线下界即可入。
**关键区别**：用「按账号收到时间（`receivedAt`）下界」而非「固定年龄窗」——停机期间**收到**的邮件其 `receivedAt` 在水位线之后，
故仍入摘要；只有接入前的历史积压被排除。

**时间戳口径**：摘要层下界是**精确**的，落在 `receivedAt`（来自邮件 `Date:` 头，缺失/不可解析时回落到摄入时刻 `now()`）；
这与摄入层的**粗粒度**下界（IMAP `SINCE` 按 INTERNALDATE 日期粒度、Gmail `after:` 按内部收到时间）是**不同时间戳**，三者
（IMAP INTERNALDATE / Gmail 内部时间 / 摘要 `Date:` 头）可在水位线附近 ±1 天内不一致——这是 best-effort 取舍（design 决策 5），
不为对齐它们而加 post-fetch 过滤。两个方向都接受：①边界邮件被摄入多收 ≤1 天；②**一封 INTERNALDATE ≥ processFrom 过了摄入、但
`Date:` 头 `receivedAt < processFrom` 的邮件会被处理（甚至实时推送）却不进摘要**——后者较反直觉但同属水位线附近的 best-effort 不一致、可接受。
对在**停机窗内接入**的账号，其 `processFrom` 落在停机期内，停机前收到的邮件被排除——这是对原「停机积压不被永久排除」契约的**有意**收窄
（接入即起算），非 bug。

#### 场景:到点触发并推送
- **当** 到达某个 `DIGEST_TIMES` 时刻且存在 P1/P2 邮件或 P3 计数 > 0 的未进过摘要邮件
- **那么** 系统必须组装摘要并经通知渠道推送

#### 场景:无新邮件不推送
- **当** 到达某时刻但无 P1/P2 邮件且 P3 计数为 0
- **那么** 系统**禁止**推送（不发空摘要）；记一条结构化日志

#### 场景:停机超过一天的积压邮件仍入摘要
- **当** 进程停机超过 24 小时后恢复，期间有未进过摘要的已处理邮件，且这些邮件的 `receivedAt` 在其账号 `processFrom` 之后（停机期间收到）
- **那么** 这些邮件必须仍被纳入下一次摘要（**禁止**因年龄被永久排除——按收到时间下界而非固定年龄窗，故停机积压不受影响）

#### 场景:接入前的历史积压被水位线排除
- **当** 某账号 `processFrom` 已设（接入或 `set-process-from` 盖戳），且库中存在该账号 `receivedAt < processFrom` 的已处理、未进过摘要邮件
- **那么** 这些邮件**禁止**进入摘要（即便 `processedAt != null`），使接入当天倒入的历史积压不再刷屏

#### 场景:NULL 水位线账号不设摘要下界
- **当** 某账号 `processFrom` 为 NULL
- **那么** 该账号的候选不受 `receivedAt` 下界约束（保持现状，与既有「停机积压不被永久排除」一致）

#### 场景:缺 Date 头的旧邮件其 receivedAt 回落到摄入时刻
- **当** 一封历史旧邮件缺 `Date:` 头（或不可解析），其 `receivedAt` 回落到**摄入时刻**而非真实收信时间
- **那么** 摘要下界按该回落 `receivedAt` 判定：仅当 `processFrom` 晚于其摄入时刻才被排除——故运维压存量积压时，`set-process-from` 须盖到**接入处理之后**的日期（如接入次日「今天」），才能连同这类回落 `receivedAt` 的旧邮件一并排除
