## 修改需求

### 需求:通知不泄露完整正文
通知内容必须只包含白名单结构字段——**来源邮箱标签**、主题、发件人、原因、**中文分类**、置信度,**禁止**包含完整正文（`textBody`/`htmlBody`,类型层排除不变）。

**来源邮箱标签**:渲染时优先用账号 `label`（中文别名,见 account-registry「账号可选展示别名 label」），未设则用账号 `email`（稳定必有）——二者经 `accountLabel` 投影到 payload。`accountId` 亦投影,仅作穿透链漏填时的**末位兜底**（裸 id、**绝不**渲染空来源）。**不**用 accountId-strip 作主回落（自定义 account-id 未必含邮箱、prefix-only id strip 后为空）。多账号下通知必须可辨来源。

**渲染净化（单点防御,choke point）**:来源标签(无论来自 `label` / `email` / 裸 accountId)在**渲染边界**必须净化——剥除 `\p{Cc}` / `\p{Cf}` / U+2028 / U+2029 / U+2066–U+2069。`label` 已在 add 处按 denylist 校验、`accountId` 已严格 ASCII,但账号 `email` 是 IMAP 运维自由文本(`--email` 在 add 处**未**按此 denylist 校验、原样存),若直接渲染会经 email 重开 RTL-override 等来源伪装面;故须在渲染单点统一净化(覆盖 email、label、裸 id 及未来任何来源字段)。

**中文分类**:category 英文枚举经**单点映射**渲染为**中文** hashtag（映射覆盖全部 category 枚举臂；新增枚举臂无映射必须构建期失败），如 `#系统告警`/`#交易`/`#安全`/`#营销`；**禁止**直接渲染英文枚举名。

**单一模板**:P0 与 P4 必须共用同一字段模板（消除现两分支字段分歧）；`riskFlags` **非空才**渲染风险行；**仅 P4** 附「不要点击链接、请直接进官网/客户端核验」类安全提示。label / 邮箱标签 / 分类均为结构字段,不引入正文。

#### 场景:通知指明来源邮箱（未设 label）
- **当** 推送任一通知、且其账号未设 `label`
- **那么** 通知必须含账号 `email` 作来源标签；**禁止**不显示来源 / 渲染空字符串（穿透链漏填时末位回落裸 `accountId`、仍非空）

#### 场景:来源标签渲染前净化（防 email 携注入字符）
- **当** 账号 `email`（或任何来源字段）含 `\p{Cc}` / `\p{Cf}` / bidi / 行分隔字符（如经未校验的 IMAP `--email` 注入 RTL-override U+202E）
- **那么** 渲染的来源标签必须已剥除这些字符;**禁止**未净化的 email 直接进通知行（防经未校验的 `--email` 做来源伪装）
- **且** 净化须在 fallback **之前**(先净化候选、净化后为空才回落):若来源标签净化后为空（如全 bidi/控制字符的 email），必须回落非空 `accountId`（ASCII、净化 no-op）——**绝不渲染空来源**;**禁止**把净化包在整个 fallback 外层（否则全危险字符的候选 pre-sanitize 非空被选中、再净化成空 → 空来源）

#### 场景:中文别名优先
- **当** 账号设了 `label`（如「公司邮箱」）并推送其一封通知
- **那么** 来源标签必须渲染该 `label`，而非派生标签

#### 场景:分类渲染中文
- **当** 推送任意 category 的通知
- **那么** 必须渲染对应**中文** hashtag；**禁止**渲染英文枚举名（如 `system_alert`）

#### 场景:P0/P4 单一模板、风险行条件显示
- **当** 推送 P0 或 P4 通知
- **那么** 必须用同一字段模板；`riskFlags` 为空时**不**渲染风险行、非空才渲染；**仅** P4 附安全核验提示

#### 场景:不含完整正文（不变）
- **当** 推送任意通知
- **那么** 通知 payload 与渲染文本**禁止**含 `textBody`/`htmlBody` 完整正文
